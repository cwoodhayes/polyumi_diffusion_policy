# PolyUMI Diffusion Policy

Diffusion policy forked from [UMI](https://umi-gripper.github.io/)'s visuomotor implementation, extended with contact-mic audio, a finger camera, and gripper-only action spaces.

### PolyUMI Fork Notes:
- Deleted code & deps not needed for training or inference; pinned deps that no longer built (protobuf, huggingface_hub)
- Added `serve_policy.py`, a `PolicyBackend` for PolyUMI's `polyumi_inference` protocol (obs translation, checkpoint load, `/reset`), plus a Dockerfile/entrypoints (`docker/train.sh`, `docker/serve.sh`) so training and serving run the same image
- Retuned the PolyUMI export config (`obs_down_sample_steps` for the 30 Hz export, val_loss re-enabled) and added per-request timing to the serve path
- Added contact-mic audio as a modality: a `type: audio` obs key routes to the new `MelAudioEncoder` (`diffusion_policy/model/audio/`), which concatenates the `mic_0` waveform rows and takes log-mel through a small CNN stem. Built on torch primitives rather than torchaudio — a new dependency would invalidate every dill-pickled checkpoint — with parameters matching ingest's `config/contact_audio.yaml`, and the same row-concatenation strategy as the Vista fork's `vista/preproc/log_mel.py`. Audio gets an identity normalizer, not a range one: a waveform's columns are successive time offsets, not channels
- Added gripper-only policies: a task declaring no `*_eef_pos` now trains end to end, with the action being the gripper-width column alone and `action_gripper_repr: abs|relative` choosing between the width itself and the change from the width observed at `t_obs`. Everywhere that assumed a `[pos3, rot6d, width]` action now branches on `num_robot == 0` — action construction in `common/sampler.py`, the action normalizer and `demo_start_pose` sampling in `dataset/umi_dataset.py`, and the workspace's action-MSE logging
- Added 13 task configs for the slip-control, board-wiping and tactile/audio ablations (`config/task/polyumi_*.yaml`), each with a workspace config per the one-workspace-per-task convention of the file they were copied from. Those workspace copies hold nothing unique: `--config-name=train_diffusion_unet_timm_polyumi_workspace task=<name>` composes an identical config. 
- Extended the serve path to those checkpoints: `serve_obs.py` takes optional `finger_rgb` / `mic_0` channels and an optional image, and `serve_policy.py` reads which channels a checkpoint wants from the checkpoint's own encoder rather than a flag, so a visuomotor checkpoint keeps working unchanged. It also syncs BatchNorm running statistics into the EMA weights before serving — `EMAModel.step` averages parameters only, so the EMA buffers never tracked the data and validation never sees it (`test/test_serve_bn_sync.py`). PolyUMI's own docs cover how the serve path is launched and wired
